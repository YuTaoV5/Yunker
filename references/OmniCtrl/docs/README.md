> 面向 MCU 的轻量级控制中间件，通过算子化设计与图形化控制拓扑，将控制算法实现与具体控制逻辑进行分离。

# ✨ OmniCtrl 是什么？

OmniCtrl 是一个面向 MCU 的轻量级控制中间件，最初的想法来源于电子设计竞赛：希望做一个可以通过通信直接控制电机运动的通用控制器，让使用者不必反复关注底层控制代码。

后来在学习和尝试不同控制系统的过程中，我发现每次改变 PID、滤波、限幅等模块之间的组合关系，都需要重新修改程序、编译和烧录，十分繁琐。于是有了 OmniCtrl —— **将具体的控制功能与它们之间的组合方式分离，让控制系统可以更加自由地搭建和调整。**

OmniCtrl 提供配套的图形化 Studio，可以通过拖拽和连线设计控制结构；同时尽量减少对具体芯片和开发平台的依赖，便于移植到不同的 MCU 工程中。

## 特点

- **图形化设计**：通过拖拽和连线快速搭建控制结构；
    
- **灵活组合**：PID、滤波、限幅等控制功能可以按需求自由组合；
    
- **配置即可使用**：已有功能能够满足需求时，无需修改中间件代码；
    
- **平台无关**：不绑定特定 MCU 或厂商开发平台；
    
- **快速移植**：只需提供少量必要接口即可接入新的工程。
    

> **OmniCtrl 希望让控制系统的尝试和调整更加简单，而不是每改变一次控制结构，都重新组织一遍程序。**

# 🧩 工作流程

OmniCtrl 的完整使用流程可以概括为四个步骤：

## 1. 配置控制功能

根据项目需求选择需要使用的 PID、滤波、限幅等控制功能，并配置需要参与控制的工程数据。

如果现有功能已经能够满足需求，整个过程只需要修改配置文件，无需修改 OmniCtrl 本身。

## 2. 接入 MCU 工程

将 OmniCtrl 加入目标 MCU 工程，并提供少量必要接口，例如通信、控制数据加载以及模式切换等功能。

完成初始化后，只需要在合适的位置周期调用 OmniCtrl 的更新函数，即可让控制逻辑随程序正常执行。

> 这一部分通常只需要少量接入代码，OmniCtrl 本身不依赖特定 MCU 或厂商平台。

## 3. 使用 Studio 设计控制拓扑

将当前工程的配置提供给 OmniCtrl Studio，Studio 会自动获得该工程可以使用的控制功能。

随后即可通过拖拽和连线搭建需要的控制结构，例如：

```text
目标值 -> PID -> 限幅 -> 输出
```

完成设计后，Studio 会生成对应的控制拓扑数据。

## 4. 部署并运行

通过 UART、RS485、USB、CAN 等适合当前设备的方式，将生成的控制拓扑数据发送到 MCU，设备重新启动后即可按照新的控制结构运行，不需要再次修改 MCU 程序。

# 🌱 项目背景

OmniCtrl 来源于本科毕业设计中的嵌入式控制系统研究，并在双路直流电机控制器中完成了实际应用与验证。

项目曾获得**优秀毕业设计**。

目前开源版本在原项目基础上重新整理，希望将 OmniCtrl 与具体硬件应用进行区分，使其能够作为一个独立的控制中间件进行学习、使用和进一步开发。
